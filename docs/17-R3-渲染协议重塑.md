# 17 · R3 渲染协议重塑

> 前置：R1、R2 完成。本包改的是"渲染层的接口形状"——趁消费者少（目前只有 devtools
> 与测试），把协议改对；等 GL/Skia 后端和更多组件上来再改就是破坏性变更。

## R3.1 RasterBackend 协议改为 docs/03 §2 的形态

**根因**：`gfx/raster/base.py:47-52` 的协议只有一个 `rasterize(display_list) -> FrameBuffer`
——返回 CPU bytearray。GL/Skia 后端在结构上无法实现"把像素读回内存"作为唯一接口；
脏矩形、DPI scale、位图资源生命周期全部缺席。docs/03 §2 描述的协议是对的，代码是错的。

**目标形态**（与 docs/03 §2 对齐）：

```python
class RasterBackend(Protocol):
    def begin_frame(self, size: Size, scale: float) -> None: ...
    def execute(self, display_list: DisplayList, clip: Rect | None) -> None: ...
    def end_frame(self) -> None: ...
    def screenshot(self) -> FrameBuffer: ...          # 读回是显式操作，不是唯一接口
    def create_image(self, ...) -> int: ...           # 位图资源生命周期（最小实现可先抛）
    def destroy_image(self, handle: int) -> None: ...
```

已拍板的决策（docs/14 §4）：

- **帧缓冲所有权在后端**，`screenshot()` 是读回操作；
- **脏矩形是 `execute` 的参数**，不进显示列表——显示列表保持"纯图纸"，
  黄金图比对语义不被污染。

**修法**：

1. 重写 `gfx/raster/base.py` 协议；
2. `SoftwareRasterizer` 改造为新协议（内部仍可先全量光栅，`clip` 先只作用于最终合成）；
3. `devtools/screenshot.py` 适配（begin→execute→screenshot）；
4. `gfx/__init__.py` 公开 API 同步更新——这是对外的契口，变更要在 docstring 里写清；
5. 删除或重写 `gl_backend.py` / `skia_backend.py` 空壳的 docstring，使其描述新协议
   （仍不实现）。

**测试**：协议形状测试（方法签名存在性）；devtools 截图端到端不回归（黄金图全绿）。

## R3.2 `PositionedGlyph` 加 `y_offset`

**根因**：`display_list.py:64-82` 的 `PositionedGlyph` 有 `x`/`advance`，**没有 y_offset**。
HarfBuzz 的输出是 (x_offset, y_offset, x_advance, y_advance)——上下标、组合符、
CJK 标点、多字体回退的基线差都需要它。R4（文本栈替换）落地即撞墙。

**修法**：

1. `PositionedGlyph` 增加 `y_offset: float = 0.0`（带默认值，向后兼容）；
2. 软件光栅 `_blit_mask` 的落位改为使用 `y_offset`；
3. 同批把 `_blit_mask` 里对掩码原点的 `round()`（software.py:277-278）改为
   **保留亚像素**的策略：笔位置的亚像素部分应体现在掩码采样相位里而非落位时丢弃——
   完整方案依赖 R4 的 FreeType 掩码，本包的最小改动是：掩码原点不再强制 round，
   由 `rect_of_mask` 保留浮点，光栅合成时按浮点权重混合。
   若该改动引起黄金图 1px 抖动，走基线更新流程并肉眼确认。

**测试**：y_offset ≠ 0 的字形在画布上确实纵向偏移；亚像素笔位的合成测试。

## R3.3 transform 指令（最小：平移 + 等比缩放）

**根因**：录制器只有 translate（paint.py:53），整个 gfx 层没有 scale 概念——
125%/150% DPI 缩放（docs/03 §5 有整节承诺）无处可挂，motion/ 的缩放动画也无从表达。

**修法**：

1. 录制器的变换栈从"累计平移"升级为"2×3 仿射矩阵"（(a,b,c,d,tx,ty) 元组，
   frozen、可 ==、可序列化——与显示列表的确定性纪律一致）；
2. 现阶段只暴露 `translate` 与 `scale` 两个操作（旋转暂缓），但数据结构按全仿射留位；
3. 每条指令在录制时把几何折算到设备像素（现状就是这么做的，只是换成矩阵乘法）。

**测试**：scale(2.0) 下 10×10 矩形光栅为 20×20；translate+scale 复合顺序正确；
黄金图不回归（scale=1 时逐像素相同）。

## R3.4 path 指令的数据形态（只定形状，不实现光栅）

**决策（已定）**：扁平 verb 数组——`(verb, *coords)` 元组序列，
verb ∈ {M, L, Q, C, Z}。**不接受 SVG path 字符串**：解析与等值比对的复杂度不许进渲染层。
这是 `icons/stroke.py`（docs/13 承诺的 SVG 图标）的载体前置。

**修法**：`display_list.py` 增加 `PathFillOp`/`PathStrokeOp` 指令类型与序列化支持；
软件光栅端**暂不实现**（执行时抛明确的 `NotImplementedError` 而非静默跳过）；
icons 落地（后续工作包）时再实现光栅。

## R3.5 软件光栅快路径

**根因（审查实测，1280×800）**：全屏不透明填充 **749ms**；50 张圆角卡片+描边 1596ms；
组合场景约 3.4s/帧（预算 14ms）。`_accumulate`/`_paint_row`/`_clear` 全部逐像素
Python 循环，切片快路径被逐像素扫描抵消。

**修法**：

1. **不透明矩形直通**：`FillRectOp` 满足 radius=0、α=255、clip 为 None 时，
   按行切片整体赋值（`buf[row_start:row_end] = pixel * w`），不走逐像素；
2. `_clear` 同理整块填充；
3. 描边/圆角路径保持现状（正确性优先），但把明显的热点循环能做切片化的做掉；
4. **不引 numpy**（`dependencies = []` 是明确原则）。

**验收**：新增 `-m slow` 性能用例：1280×800 全屏填充 < 50ms（从 749ms 降一个数量级，
仍留 CI 余量）；黄金图逐像素不回归（这是正确性约束，快路径不许改变任何一个像素）。
