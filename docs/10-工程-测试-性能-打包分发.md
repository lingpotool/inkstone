# 10 · 工程：测试 · 性能 · 打包分发

> 一句话：**"能跑"和"敢发版"之间，隔着一整套质量体系。**

## 1. 测试金字塔

```
        ╱ 平台测试 ╲        真窗口、真输入法、真读屏（带显示的 runner）
       ╱  集成测试  ╲       headless 后端驱动完整 App 场景
      ╱   黄金图     ╲      确定性截图，三平台基线一致
     ╱   单元测试     ╲     布局/文本/样式/状态，无窗口
```

铁律：**能往下层测的，不许往上层抬。** 一个布局 bug 用黄金图抓，是浪费；用单测抓，是一毫秒。

## 2. 黄金图机制

- headless 后端离屏渲染 → 与基线逐像素比对 → 超容差即失败并产出 diff 图。
- 确定性三件套：注入时钟、注入随机源、锁定字体——缺一个，截图就在三台机器上三个样。
- 基线更新必须显式（`make golden`）+ PR 说明变更原因，防止"顺手更新基线"掩盖回归。
- 目标覆盖：1.0 时 ≥ 200 场景（组件 × 变体 × 状态 × 明暗）。

## 3. 性能预算（目标机：核显笔记本，60fps）

| 指标 | 预算 |
|---|---|
| 帧时间（200 节点交互） | p95 < 8ms |
| 帧时间（1000 节点交互） | p95 < 16.6ms |
| 全量布局（1000 节点） | < 5ms |
| 10 万行表格滚动 | p95 < 16.6ms |
| 冷启动到首帧 | < 400ms |
| 内存（空窗口 / 1000 节点） | < 60MB / < 150MB |

- profiler 内置：超支时能定位到阶段 → 层 → 节点；
- 性能回归进 CI：基准测试比 main 慢 10% 即报警。

## 4. CI 矩阵

- 平台：Windows 11 / macOS 13+ / Ubuntu 22.04（X11 + Wayland）
- Python：3.10 / 3.11 / 3.12 / 3.13
- 每个 PR：`lint + mypy --strict + 单测 + 黄金图`；每晚：`集成 + 性能基准`；发布前：`平台测试清单`。

## 5. 打包与分发

### 库本身（pip 包）
- wheel 零依赖核心；SDL2 / Skia 作为可选 extra；
- 原生依赖用 `auditwheel`（Linux）/ `delocate`（macOS）/ `delvewheel`（Windows）内嵌；
- 内嵌字体必须 OFL 等可再分发许可。

### 应用（用户拿 Inkstone 做的软件）
- `inkstone build`：PyInstaller/Nuitka 打包 → `.exe`（Authenticode 签名）/ `.app`（公证 notarization）/ `.AppImage` + `.deb`；
- 签名与公证是"真的可以发布"的硬门槛，列入 Phase 3 交付，不留到"以后"。

## 6. 版本与弃用政策

- SemVer；`0.x` 允许破坏性变更但必须在 CHANGELOG 写迁移方式；
- `1.0` 后：破坏性变更先经一个次版本的 DeprecationWarning；
- LTS：1.0 起 12 个月安全与崩溃修复。
