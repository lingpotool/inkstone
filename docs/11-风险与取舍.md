# 11 · 风险与取舍

> 一句话：**把会翻车的地方提前写下来，翻车时才不至于变成事故。**

## 1. 风险登记表

| 风险 | 概率 | 影响 | 缓解 | 止损线 |
|---|---|---|---|---|
| IME 三平台行为不一致，调试期爆炸 | 高 | 高 | Phase 1 就建真机测试清单；统一内部组合模型 | 若 Wayland 持续失控 → 首发声明 X11 支持、Wayland 标记 beta |
| SDL2 二进制分发（macOS 签名/Linux 依赖） | 中 | 高 | 早期就做打包验证，不留到 Phase 3 | 备选：让用户装系统 SDL，wheel 只带绑定 |

## 2. 止损线（什么情况下承认此路不通）

1. **性能止损线**：Phase 2 末，1000 节点交互帧 p95 仍 > 25ms 且缓存手段用尽 → 启动 Cython/原生扩展，不再坚持"纯 Python 热路径"。
2. **平台止损线**：某平台 IME 连续两个里程碑无法达到"可用" → 该平台降级为 beta，不拖死三平台整体发布。
3. **范围止损线**：Phase 3 中期检查，若 Tier 3 高级组件完成度 < 50% → 1.0 砍 Chart/Markdown/CodeBlock，作为 1.1 交付。
4. **整体止损线**：若出现维护良好的同类项目（纯 Python、自绘、跨平台、中文友好）达到同等成熟度 → 评估合流，不为了"自己的库"而坚持。

## 3. 取舍记录（明确不做什么，以及为什么）

| 不做 | 原因 |
|---|---|
| 移动端（iOS/Android） | 触摸、生命周期、输入法模型完全不同，做了就是第二个项目 |
| 浏览器/WebAssembly 后端 | 与浏览器 DOM 模型冲突，等于重写 |
| 全局 CSS 选择器 | 优先级玄学，对 AI 与测试都不友好（见 `docs/07`） |
| 自研文本整形/断行 | 上千条规则，复用成熟实现是止损不是偷懒（见 `docs/04`） |
| 游戏级渲染（3D/粒子/自定义着色器编排） | 超出 UI 库职责 |
| 兼容 Python < 3.10 | dataclass slots、match、类型语法都要求 3.10+ |

## 4. 给非技术读者的翻译

- 这份文档存在的意义：**承认会出事，并提前决定"出多大事就换路"**。
- 没有这份文档的项目，遇到风险时的决策是"再撑撑看"——那是最贵的决策方式。
- 止损不是失败，是把损失锁在已知范围内。
