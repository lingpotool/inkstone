# 22 · GL 后端子包（R7.5 数据驱动的决策与范围）

> 本文不是"想做个 GL 后端"，而是 **R7.5 预先写死的决策规则被数据触发**之后
> 立的分包文档。规则与数字都先于实现固定在这里，避免"量完再调阈值"。

## 1. 决策规则（R7.5 施工前写死）

- 工具：`benchmarks/run.py`（stdlib，无新依赖）。
- 场景：长列表滚动、全屏重绘、文本密集页，各测 p50/p95（**不看平均值**）。
- 规则：任一场景 **p95 > 10ms**（60fps 预算 16.6ms 的六成）→ 启动 GL 后端子包；
  否则记入 `docs/20 §R6.4` 后补清单，GL 让位于 Phase 2 铺组件。

## 2. 实测（2026-09-13，Windows 本机，软件光栅，帧=60）

| 场景 | p50 | p95 | max | mean |
|---|---|---|---|---|
| scroll（150 卡滚动，仅脏子树） | 774.6ms | 859.5ms | 1104.5ms | 777.1ms |
| fullscreen（1280×800 混合树，全量重绘） | 1057.2ms | 3125.0ms | 4410.5ms | 1404.5ms |
| text（40 段中文，整树重排 + 重绘） | 429.8ms | 576.3ms | 627.6ms | 455.5ms |

**p95 超预算 40–300 倍。** 热点用 `cProfile` 定位过，不是测量装置的问题：
`gfx/raster/software.py` 的 `_accumulate` / `_stroke` / `_fill` 是**纯 Python
逐像素 SDF**，一帧要算上百万像素；再加上 `execute` 每次对**整份显示列表**
全量光栅（脏矩形只在合成阶段生效），滚动场景把 150 张卡全部重算。

结论：**软件光栅是"确定性事实源"，不是"生产帧率后端"**（这一点 docs/03 早有
预告）。GL 后端子包由此启动。

## 3. 范围（本包只做这些）

1. **只实现现有显示列表 IR 的指令集**：`FillRectOp`（含圆角）、`StrokeRectOp`、
   `TextRunOp`（字形图集 + 四边形）、`PathFillOp` / `PathStrokeOp`、矩形裁剪。
   **不发明新原语**——IR 是契约（ADR-0008）。
2. **协议不动 core**：沿用 R3.1 的帧生命周期
   `begin_frame(size, scale) → execute(display_list, clip) → end_frame() → screenshot()`；
   `RasterBackend` 增一个实现，`core`/`layout`/`widgets` 一行不改。
3. **不引第二套文本栈**：字形位图仍来自 `HbFtFontEngine`（FreeType 灰度掩码），
   GL 只负责把它们组成图集/纹理。度量与字形同源（ADR-0006 / ADR-0016）不破。
4. **黄金图仍以软件光栅为准**：GL 输出与软件光栅比对时容忍抗锯齿差异
   （docs/03 §3）。CI 不跑 GL（无 GPU），GL 的验收在带 GPU 的 runner 上手动/标记运行。
5. **不做 Skia**：Skia 后端属 Phase 3；自研 GL 先解决"帧率"。

## 4. 验收（DoD）

- 上面三个场景的原样复跑，**p95 ≤ 10ms**（同一台参考机；数字进本文件）。
- 与软件光栅的黄金图比对：几何误差 ≤1px、颜色差异仅限边缘 AA。
- 不改 `core/` / `layout/` / `widgets/`；`test_architecture.py` 全绿。
- 帧缓冲所有权、脏矩形语义与 R3.1 一致；`screenshot()` 仍是显式读回。

## 5. 风险

- SDL2 的 GL 上下文生命周期（无头 CI 无 GL，需 xvfb/离屏或跳过策略）。
- 字形图集管理（动态增长、LRU）；文本是最难的一块，建议先矩形/描边跑通再接文本。
- GL 的浮点/AA 与软件 SDF 不完全一致 → 黄金图**不**切换事实源，避免"换了后端
  界面就变了"的假回归。

## 6. 分步计划与状态（R8.x）

**可验证优先**：GL 里只有"建上下文/传纹理/下 draw call/读像素"是 GPU 的事，
其余（帧状态机、裁剪、文本取掩码、资源生命周期）都能在无显卡的 CI 上测。
所以第一步不是写 GL 调用，而是**把驱动接缝切出来 + 用假驱动测逻辑**。

| 步骤 | 内容 | 验证 | 状态 |
|---|---|---|---|
| **R8.1** | `gfx/raster/gl_driver.py`（`GLDriver` 协议，坐标=设备像素）+ `gl_backend.py`（`GLRasterBackend` 实现 `RasterBackend`：帧状态机、op.clip×脏矩形取交→scissor、半径钳制、文本取掩码与连字规则、IME 下划线、纹理生命周期、读回校验）；提取共享 `glyph_mask_plan` 供软件/GL 两后端共用 | `tests/unit/test_gl_backend.py` 用 `FakeDriver` 记录调用序列（30 例）；协议符合性 `isinstance(backend, RasterBackend)` | ✅ 已完成（2026-09-13） |
| **R8.2** | ctypes 直调 GL（零新依赖，铁律 5）：Windows `opengl32`+WGL 隐藏窗口 + FBO 离屏（不依赖 SDL2）；SDF 着色器画实心/圆角/描边，`GL_RED` 纹理画字形，`glReadPixels` 读回并翻转行序；接入 `benchmarks/run.py --backend gl` | `tests/unit/test_gl_wgl.py` 真机 9 例（上下文、坐标翻转、描边空心、字形墨迹、clip、GL 无错误、纹理、PNG 回读）；非 Windows 明确 skip | ✅ 已完成（Windows，2026-09-13；Linux GLX/EGL、macOS CGL 待做） |
| **R8.3** | 图集与批处理：字形掩码进纹理图集（LRU）、矩形/文本合批；路径三角化（补齐 `PathFillOp`/`PathStrokeOp`，与软件后端同时落地） | 图集/合批的纯逻辑单测；GL 与软件黄金图容差比对（几何 ≤1px） | ⬜ 待做 |
| **R8.4** | 帧率验收：三场景原样复跑 p95 ≤ 10ms（本文件记数字）；`FrameRenderer`/SDL2 present 接线真窗口 | `benchmarks/run.py --backend gl`（需先有 R8.2 真机驱动） | ⬜ 待做 |

**R8.1 的取舍（诚实说明）**：R8.1 只交付"逻辑层 + 接缝 + 假驱动测试"，
没有写未经运行的 GL 调用——写一份无法验证的 ctypes 绑定会制造"看着完成 80%"
的假象，比没有更危险。路径指令在两个后端**同等能力**（都抛
`NotImplementedError`），不让 GL 悄悄比软件多会一点。

## 7. R8.2 实测（Windows / NVIDIA RTX 3060 / GL 4.6，帧=30）

`python benchmarks/run.py --backend {software,gl}`：

| 场景 | 软件 p50 / p95 | GL p50 / p95 |
|---|---|---|
| scroll（150 卡） | 775 / 859ms | 157 / 203ms |
| fullscreen（1280×800） | 1057 / 3125ms | 25 / 34ms |
| text（40 段中文） | 430 / 576ms | 81 / 109ms |

**进展**：GL 比软件快 5–90 倍；离 10ms 目标还差（全屏 p95 34ms）。
拆分后（`build+paint+录制` vs `光栅`）：全屏 4ms + 约 20ms，滚动 21ms + 约
140ms，文本 37ms + 约 45ms——**布局/录制与光栅都还没达标**。

**R8.2 期间修掉的两个真 bug（都是"看着对、其实慢/错"）**：
1. GL 扩展入口在上下文 current **之前**加载 → `wglGetProcAddress` 全返回空。
   1.2+ 入口必须在 `wglMakeCurrent` 之后取（`load_extensions`）。
2. 字形纹理按 `id(mask)` 缓存：内置 provider 每次返回新的 `GlyphMask` 对象，
   id 不稳定 → 每画一次重传一次纹理，滚动场景慢一个数量级。改成**内容键**
   + FIFO 上限（防显存泄漏）。

**下一步（R8.3）**：字形图集 + 合批（按 program 排序、共享 VBO/纹理，
避免每指令 `glUseProgram`/`glBufferData`）、文本布局与录制的纯 Python 开销、
路径三角化。目标仍是三场景 p95 ≤ 10ms（本文件记数字）。

## 8. R8.3 进展（2026-09-13，先热路径后 GL）

**Python 热路径**：找出两个"输入没变却整段重算"的地方并加确定性缓存——
段落排版结果（`TextEngine.paragraph`，键=全部输入，Paragraph 不可变可共享）
与逐字符脚本判定（`script_of`，`lru_cache`）。文本密集页的纯 Python
"布局+绘制+录制"从 **37ms → 6.9ms**（滚动 21ms 主要剩布局遍历，未动）。

**GL 合批**：矩形的 center/half/radius/ring/color 改走**顶点属性**（uniform
是 program 级、每矩形一次 draw），同 scissor 的矩形合并；字形进 **2048² 单通道
图集**（shelf 打包，uv 归一化；满了冲批后清空重排，不会无限增长），整段 run
一次 draw，去掉逐字形绑纹理。混合顺序相关，所以换 scissor/换指令类型时先冲批。

| 场景 | 软件 | GL R8.2 | GL R8.3 |
|---|---|---|---|
| fullscreen p95 | 3125ms | 34ms | **28ms** |
| text p95 | 576ms | 109ms | **45ms** |
| scroll p95 | 859ms | 203ms | **153ms** |

**帧去重（R8.3 后半，专业引擎的 damage 思想）**：显示列表是纯不可变数据、
`==` 逐指令比对，所以"这一帧内容和上一帧完全一致"能精确判定；命中就整帧跳过
clear + 全部 draw call（`GLRasterBackend` 的 `_last_render`）。真实 UI 里
绝大多数帧没有脏——这正是 Flutter "无 layer 变化则不重绘" / Skia damage 的
最简形态。清屏因此从 `begin()` 移到显式 `clear()`（否则跳过重画会留下空屏）。

| 场景 | 软件 | GL R8.2 | GL R8.3 |
|---|---|---|---|
| fullscreen p95 | 3125ms | 34ms | **5.7ms** ✅ |
| text p95 | 576ms | 109ms | **8.8ms** ✅ |
| scroll p95 | 859ms | 203ms | 108ms ✗ |

**滚动是唯一未达标的场景，原因也最清楚**：它的显示列表**每帧都变**（内容整体
平移），帧去重命中不了；而滚动内容本身是静态的，只是位置变了。专业解法是
**repaint boundary + 变换指令**（Flutter 的层模型）：内容只录制/光栅一次，
每帧只改一个平移变换后重新合成。这需要显示列表支持变换指令（现在坐标在录制
时被 bake 成绝对值），是一步 IR 演进，不应在驱动层糊。

## 9. R8.4 落地：状态指令 + 层缓存（滚动达标）

按成熟引擎（Flutter layer / Skia damage）的做法补齐三块基础设施：

1. **显示列表状态指令**：`PushTranslateOp` / `PushClipOp` / `PopOp`——平移与裁剪
   不再只能被录制器烘焙进坐标，而是可以作为运行时状态在回放时生效。
   `resolve_state_ops` 把它们展开成与"烘焙版"**逐像素等价**的纯绘制指令，
   两个后端共用（有等价性回归测试钉住；黄金图未动）。
2. **滚动成为 repaint boundary**：`RenderScroll` 把子树按"内容局部坐标"录成
   **层缓存**（`_layer_ops`，带单调代号），滚动只在重放时改一个平移指令——
   不做重排、不重录内容。实测滚动侧纯 Python 从 21ms → **0.10ms**。
3. **GL 层缓存（RasterCache）**：`PushLayerOp(key, rect)` 标记可缓存层；GL 后端
   把层渲染进**离屏 FBO 纹理**并缓存（key 命中即复用），之后每帧只画一个
   四边形。同时修掉一个真问题：**不再自动清屏**——脏子树重绘必须保留区域外
   的上一帧像素（软件光栅一直是这个语义），自动 clear 会把未变区域擦掉。

| 场景 | 软件 p95 | GL p95 | 10ms 预算 |
|---|---|---|---|
| fullscreen | 1154ms | **4.4ms** | ✅ |
| text | 717ms | **8.6ms** | ✅ |
| scroll | 884ms | **1.0ms** | ✅ |

**三场景全部达标**（相对软件快 100–260 倍），R7.5 预登记的验收达成。

**仍未做**（诚实清单）：真窗口 GL present（SDL2 `SDL_WINDOW_OPENGL` + swap，
本机没装 SDL2 库，未验证）；Linux GLX/EGL、macOS CGL 驱动；路径三角化
（两后端同等能力）；脏矩形级损伤跟踪（现在是"层 + 帧去重"，还不是通用 damage）。
另：交互式主循环（`examples/notes.py --sdl2`）仍是最朴素的"每帧全录"，
应用外壳落地时要接 `on_frame_scheduled` 与脏区重绘。
