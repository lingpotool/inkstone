# 20 · R6 主题传播与依赖追踪

> 前置：R1（其中 R1.10 已交付最小版 theme setter）。本包做正式机制。
> 定位：R1 止血之后、Phase 2 大规模铺组件之前——这套机制每多一个组件再补，
> 成本就涨一分。

## R6.1 InheritedElement：依赖追踪机制

**根因**：R1.10 的"换主题全树标脏"是止血，不是机制。主题、locale、DPI、密度
都是"环境数据"，需要**子树作用域覆盖 + 定向标脏**：改了侧栏的主题只重建侧栏。
全代码库无 `Inherited`/`did_change_dependencies` 等价物。

**设计（Flutter 正统路线，裁剪版）**：

1. 新增 `InheritedWidget` / `InheritedElement`：Element 树维护
   `_inherited: dict[type, InheritedElement]` 索引（挂载时从父级继承 + 本地注册）；
2. 消费方在 build 时声明依赖（如 `context.depend_on(ThemeScope)`）——
   Element 记录"我依赖了哪个 InheritedElement"；
3. InheritedElement 更新时：只标脏声明过依赖的 Element；
4. `BuildOwner.theme` 迁移为根部的 `ThemeScope`（InheritedWidget），
   R1.10 的全树标脏成为它的特例（根主题变了 = 全员依赖者标脏）。

**与 signals 的关系（决策点，建议）**：docs/06 §3 的 signals 双轨制还没实现。
建议**依赖追踪只此一套**——signals 的 Effect 依赖收集与 Inherited 的依赖注册
共用同一套"读时登记、写时标脏"内核，避免两套语义打架。动工 signals 前先定这条。

**测试**：子树覆盖（侧栏暗色 + 主区亮色共存）；定向标脏（改侧栏主题，
主区 build 计数器不动）；移除 InheritedWidget 后依赖者正确回退。

## R6.2 signals 落地

`core/signals.py` 现为 8 行空壳。docs/06 §3 的承诺：高频更新走 signals，
精确到单个 RenderObject，1000 次/秒不掉帧。

**修法**：

1. `Signal[T]`：读写跟踪——render/build 期间读 = 登记依赖，写 = 标脏依赖者；
2. 帧调度集成：Effect 的 flush 时机挂在 `BuildOwner.begin_frame` 的
   build 阶段之前；
3. 与 R6.1 共用依赖内核（见上）；
4. 验收性能用例（`-m slow`）：1000 次 signal 写只触发 1 次帧、
   且只有依赖它的 RenderObject 标脏。

## R6.3 样式系统收尾

1. **`Theme.color()` 缓存**（theme.py:99 → 160-187）：frozen 对象每次调用重建
   26 键 dict，热路径每帧每控件多次分配——构造时物化一次；
2. **变体状态配方对称性**（variants.py:129-136）：HOVER/ACTIVE 对非 PRIMARY
   变体一律给中性色——DANGER hover 时危险浅底消失变成灰，与默认配方自相矛盾；
   SECONDARY 默认 bg 就是 surface_alt，hover 无反馈。逐个变体补齐状态配方，
   每个配方配 WCAG 对比度断言（走现有 `contrast_issues`）；
3. **None 覆盖语义**（resolve.py:74-80）：现在上层无法把值覆盖回 None
   （如把 e1 阴影降回 e0）。决策：引入显式 `UNSET` 哨兵区分"没填"与"填了 None"——
   参照 `core/element.py:44` 的 `_SLOT_UNCHANGED` 先例。

- devtools：inspector/hotreload 两个空壳——**实现它们，或从 wheel 发布里排除**，

**R7.4 样板 App 暴露的缺口（2026-09-13 记）**——App 不许在自身层打补丁，所以凡
"绕不过去"的都记在这里，而不是糊一个假实现：

- **通用单子容器缺失**（Container / SizedBox）：没有"固定宽高 + padding + 一个
  子级"的组件。样板 App 的侧栏宽度只能靠 `Flexible(flex=)` 比例绕开；要精确
  200px 侧栏或固定尺寸的容器就无路可走。`layout.RenderContainer` 已具备能力
  （Sizing + padding + child），缺的只是 widgets 层包装。
- **文本编辑模型不存在**（Phase 2）：`Input` 只能聚焦（R7.1 接了 IME 通道），
  不能输入、删除、移动光标。样板 App 的"新建笔记"只能预填标题。这是 Phase 1
  DoD"可输入、可删除、光标位置正确"的剩余部分。
- **滚动只有偏移**：无滚动条、无锚点保持、无过滚动回弹、无虚拟滚动（大列表会
  把所有子级都建出来）。`ScrollView` 的 widget 包装在 R7.4 补上，其余属后续。
- **App 外壳 `app.py` 仍是占位桩**：SDL2 帧循环目前暂住在 `examples/notes.py`，
  应在"应用外壳"落地时下沉为 `app/` 层（窗口生命周期 + 帧调度 + 事件泵）。
- **文本栈 face_key 缺口已在 R7.4 修**：整形按字重选面、`mask_for` 曾按 family
  重选（永远 Regular），多字重字体上"用甲的 glyph id 查乙的轮廓"→ 粗体整行
  画成别的字。修法是把整形选中的 face 标识经 `GlyphPlacement / ShapedCluster /
  PositionedGlyph` 一路带到 `mask_for(face_key=…)`；合成字体回归测试钉住
  （`test_hbft_fonts.py::TestGlyphsComeFromTheShapedFace`）。

**R7.5 性能基准结论（2026-09-13）**：三个真实场景 p95 全部远超预算是 40–300 倍
（scroll 859ms / fullscreen 3125ms / text 576ms，预算 10ms），热点是软件光栅的
纯 Python 逐像素 SDF。决策规则（先写死）触发 → **启动 GL 后端子包**，范围与验收
见 `docs/22-GL后端（R7.5决策与分包）.md`。软件光栅继续做黄金图的确定性事实源，
GL 只解决帧率；此决策不改变 core/协议。

## 完工记录（2026-09-12）

- **R6.1 InheritedElement**：`widget.py` 加 `InheritedWidget`（`update_should_notify`
  抽象方法）；`element.py` 加 `InheritedElement` 与依赖内核——每个 Element 持有
  `_inherited` 环境索引（与父级**只读共享同一张表**，InheritedElement 挂载时
  复制并注册自己，零拷贝）+ `_dependencies` 依赖集；`context.depend_on(ScopeType)`
  读时登记；InheritedElement 更新时定向标脏依赖者；依赖每次 build 重新登记、
  unmount 解除（不留悬挂引用）。`ThemeScope`（core/scope.py）落地子树主题覆盖；
  `Element.theme` 查找顺序改为 ThemeScope → BuildOwner 根主题 → 默认主题，
  R1.10 全树标脏保留为"根作用域变了"的特例。
- **R6.2 signals**：`Signal[T]` / `Computed[T]` / `Effect` 落地，与 Inherited
  共用同一套"读时登记、写时标脏"内核（element.py 的 `DependencySource` /
  `Dependent` 协议 + 依赖收集栈）。Signal 写**不做同值跳过**（原地修改后写回
  同一对象会被判等吞掉，那是静默失效）。Effect 给 owner 时排队到下一帧
  **build 之前**（`BuildOwner.flush_effects`，effect 里 set_state 同帧结算）；
  不给 owner 同步重跑。性能用例：1000 次写 = 1 次帧通知 + 1 次重建（`-m slow`）。
- **R6.3 样式收尾**：
  ① `_semantic_map` 加 `functools.cache`（SemanticTokens frozen 可哈希，
  热路径不再每帧重建 26 键 dict）；
  ② 变体状态配方对称性：hover/active/selected 逐变体补齐——SECONDARY 走中性
  色阶、GHOST 浮底提字色、OUTLINE 浮品牌软底、DANGER 用危险对**反转**（不发明
  第三种颜色）、LINK 只变字色；
  ③ `resolve.py` 引入显式 `UNSET` 哨兵："没填"与"填了 None"分开，
  None 现在是真覆盖（可把 e1 阴影降回 e0）。
- **测试**：新增 `test_inherited.py`（7）+ `test_signals.py`（12，含 slow
  性能用例）+ 变体配方与 UNSET/缓存测试（6）；测试总数 863 → 888。

**施工时抓到并已修的设计漏洞**：全变体×全状态对比度断言一写就红——
暗色主题 `primary_press`（#6366F1）是中调亮色，配 `on_primary` 只有 3.6:1。
修法不是绕开断言，而是改令牌：暗色 `primary_press` 换 brand-300（#C7D2FE，
暗色里"按得更深"= 更亮），PRIMARY 的 selected 统一改走 `primary-soft + primary`
（checked pair）。再次验证"对比度要算不要看"。

**与设计的偏差**：`BuildOwner.theme` 没有物理迁移成一个挂在根部的 ThemeScope
对象，而是保留为"隐式根作用域"——`Element.theme` 回落到它，setter 仍全树标脏。
理由：语义完全等价（根作用域变化 = 全员依赖者标脏），且不引入"根节点外面
再包一层"的结构复杂度。docs/06 §3 的描述已同步。

**验收核对**：888 测试全绿（含 slow 性能用例）；mypy strict 三平台干净；
ruff 干净。验收清单逐条：子树覆盖 ✓（含嵌套就近取值）、定向标脏 ✓
（主区零重建）、移除回退 ✓（依赖解除无悬挂）、signals 性能 ✓（1000 写 = 1 帧）、
全变体×全状态对比度 ✓（DISABLED/LOADING 按 WCAG 1.4.3 豁免非激活组件）、
docs/06 §3 与实现一致 ✓。R6.4 记账项保持记账，未升级为阻塞。
