# 06 · 组件树 · 状态 · 事件

> 一句话：**界面是三棵树、一套脏标记、一条事件流。状态变了，只有变了的那一小块重新走一遍。**

## 1. 三棵树（ADR-0003）

| 树 | 是什么 | 类比 |
|---|---|---|
| **Widget** | 不可变配置：描述"要什么样" | 图纸 |
| **Element** | 生命周期：挂载、更新、卸载、持有状态 | 工地 |
| **RenderObject** | 布局与绘制：持有几何信息 | 楼 |

为什么不是 React 式"每次全量重建再 diff"：
Python 的对象分配不便宜，全量重建 + diff 在大树上会产生每帧数千次临时对象分配。
Flutter 的"Widget 廉价重建 + Element 复用 + RenderObject 增量更新"是业界验证最充分的可变状态 UI 架构——我们采用它，但只保留两层核心（Element 与 RenderObject 在简单组件上合一）。

## 2. 生命周期与 Key

- `mount → update → unmount`；状态挂在 Element 上，Widget 变了只要类型和 Key 没变就复用。
- **Key 的作用**：列表重排时保持身份（输入框里的字不丢、滚动位置不跳）。
  规则一句话：**列表项必须给稳定 Key，给索引当 Key 等于没给。**

## 3. 状态双轨

| 机制 | 用法 | 粒度 |
|---|---|---|
| `setState` | 普通业务状态 | 标脏当前组件子树 |
| **signals**（Signal / Computed / Effect） | 高频更新（计数器、进度、行情） | 精确到单个 RenderObject |

经验法则：每秒更新超过 10 次的东西，用 signals；其余用 setState。
两套机制共享同一个帧调度与同一套"读时登记、写时标脏"内核（R6：
Inherited 环境传播与 signals 都建在 `core/element.py` 的依赖追踪协议上，
Effect 的重跑排在帧的 build 阶段之前），不许并行发明第三套。

> 状态：已实现（R6.1/R6.2，`core/signals.py` + `core/scope.py`）。
> signals 性能验收：1000 次写只触发 1 次帧、只重建依赖者（`-m slow`）。

## 4. 帧调度（BuildOwner）

```
输入事件 → 状态变更（收集脏集合）
  → build（重建脏子树）
  → layout（重排脏几何）
  → semantics（同步无障碍语义树）
  → paint（重放脏段显示列表）
  → composite（光栅与合成）
```

- 同一帧内的多次 `setState` **批处理**，只重建一次；
- 所有变更发生在"帧阶段"内，阶段外改状态直接报错（防时序 bug）；
- 时钟由后端注入（vsync 对齐），渲染不读墙上时钟（确定性）。

## 5. 事件流与手势竞技场

- **三阶段**：捕获（父→子）→ 目标 → 冒泡（子→父）。`stop_propagation` 显式叫停。
- **手势竞技场**：同一区域内的 tap / double-tap / long-press / drag / scroll 不是独立判断，而是**竞争**——
  例如列表里的按钮：按下后 8px 内抬起是 tap，超过则是列表滚动获胜，按钮收到取消。
  没有竞技场，"可滚动列表里放按钮"这种日常需求会写出玄学 bug。
- 指针统一：鼠标 / 触控 / 触控笔同一事件模型，只标记来源。

## 6. 焦点与命令

- 焦点链 = 树的遍历序 + `focus_order` 覆盖；焦点作用域（对话框打开时，焦点圈禁在内部，见 `primitives/focus_trap`）。
- **命令系统**：菜单项、快捷键、按钮共享同一个 command id 与 `enabled` 判定。
  改一处，三处同步；无障碍与自动化测试也走命令系统，不用模拟点击。

## 7. 线程模型

- **UI 单线程**：组件树、状态、渲染都只许在 UI 线程碰。
- 异步集成：`async` 任务 / 后台线程的结果，经队列 marshal 回 UI 线程再落地。
- 禁止在 UI 线程做 IO（文件、网络）；API 层面提供 `run_in_worker()`，让"顺手写个阻塞调用"这件事变得不可能。

## 8. 验收标准

- [ ] 同一帧 100 次 setState 只触发一次重建
- [ ] 列表 1000 项重排，Key 正确的输入框状态零丢失
- [x] 手势竞技场：滚动容器内嵌按钮，tap/scroll 竞争行为符合规格（有测试，R7.2）
- [ ] 阶段外改状态抛出带节点路径的错误
- [ ] signals 更新 1000 次/秒，UI 帧率不降
- [ ] 命令系统：同一命令经菜单/快捷键/按钮触发，行为一致（有测试）
