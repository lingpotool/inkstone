# 08 · 组件清单

> 一句话：**组件库不是"有多少"，是"每个都到了什么成熟度"。**
> 一个达到"生产"级的 Button，胜过二十个"差不多能用"的控件。

## 1. 成熟度等级

| 等级 | 含义 | 出库要求 |
|---|---|---|
| 实验 | 能跑，API 可能变 | 有人用 |
| 可用 | API 稳定，功能完整 | 文档 + 示例 + 单测 |
| **生产** | 可用于商业软件 | + 黄金图全变体 × 全状态 × 明暗 + 键盘可达 + 零硬编码 + 性能达标 |
| 冻结 | 只修 bug，不再加能力 | 有继任者才冻结 |

**组件入库标准（Definition of Done）**：文档、示例、单测、黄金图、键盘可达、设计令牌零硬编码、anatomy 声明、语义角色（无障碍）。八项缺一，不许标"生产"。

## 3. 依赖关系

- 所有 ◆ 组件**必须**由 `primitives/` 组合而成，不许自己重新发明弹层逻辑——这是"专业感一致"的来源。
- 所有组件**必须**走 `style/variants` 配方，样式零硬编码。
- 所有含文本的组件**必须**接入 IME 与选区几何（`docs/04`）。

## 4. 验收标准

- [ ] 1.0 发布时 Tier 0–3 全部达到"生产"级
- [ ] 每个组件有 anatomy 声明，且在检查器中可查看 parts 与 data 属性
- [ ] 每个 ◆ 组件的弹层行为（Escape、点击外部、焦点归还）全库一致，有共享测试
- [ ] 组件示例库可运行：不用鼠标完成全部操作
