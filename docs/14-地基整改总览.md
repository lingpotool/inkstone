# 14 · 地基整改总览（施工总纲）

> 本文档是 2026-09-12 地基审查的产物：**五路并行架构审查 + 字体栈深读 + HarfBuzz/FreeType 可行性 spike**。
> 它不是讨论稿，是**施工总纲**——每个工作包（R1–R6）都有独立的分包文档（docs/15–20），
> 细到"零上下文的施工 agent 也能正确执行"。

## 1. 审查总结论

项目的**图纸是专业级的**（显示列表作为 IR、约束模型、三棵树复用算法、注入式时钟、
令牌对比度校验、"度量同源"的结构化保证）。但执行层存在三类地基裂缝：

### 裂缝一：静默断链（表面正常，实际不通）

| 断链 | 位置 | 后果 |
|---|---|---|
| layout 脏标记不联动 paint | `layout/box.py` mark_needs_layout | 滚动、resize 后画面不刷新 |
| `RenderObjectElement.update` 不标 layout | `core/element.py:336-342` | 改几何属性静默失效（实测：width 10→200，两帧后仍是 10） |
| `_sync_children` 复用时不传 slot | `core/element.py:469-478` | flex 权重改了不生效（实测：[1,2]→[3,1] 布局不变） |
| 主题切换不触发任何标脏 | `core/binding.py:87` | "换肤"承诺的机制不存在，且静默失败 |
| IME 通路物理不通 | `backend/sdl2.py` 从未调 `SDL_StartTextInput` | 中文输入在真后端上是死的 |
| 像素上屏路径不存在 | `Backend` 协议无 present/swap | 目前唯一出图口是 devtools 截图 |

### 裂缝二：假保证（声称有地基，实际没有）

| 声称 | 实际 |
|---|---|
| "1001 节点全量布局 0.89ms" | 基准只标脏了根节点，测的是缓存命中；真全量实测 **14.6ms**，超 docs/05 的 5ms 预算近 3 倍 |
| 黄金图"三平台逐字节一致" | 比对的是 `zlib.compress` 输出字节，zlib 版本未钉——跨平台是侥幸不是保证 |
| 黄金图门禁 | **基线文件缺失时直接绿灯**（顺手把新基线写进工作区） |
| `SDL2Backend` 是 `Backend` 协议的实现者 | 它没有协议要求的四个字体度量方法——生产后端连字都量不了 |
| "组件零硬编码" | CI 只扫颜色字面量；圆角回退、描边宽度等数值硬编码有漏网活代码 |

### 裂缝三：协议画错 / 真 bug

- 软件光栅**宽高参数传反**（`gfx/raster/software.py:150,186`）：内容溢出画布底部直接崩溃——滚动列表第一天就踩中；
- 软件光栅无快路径：全屏填充实测 **749ms**（预算 8ms），一帧真实界面约 3.4s；
- `RasterBackend` 协议形状错误：`rasterize() -> FrameBuffer` 返回 CPU 像素，docs/03 §2 承诺的 begin/execute/end 形态在代码里不存在；
- `PositionedGlyph` 缺 `y_offset`——HarfBuzz 落地即撞墙；
- 事件模型缺 `window_id`；时间戳取自泵时刻而非事件本身；macOS 滚轮方向反的；`wait_events` 每唤醒一次稳定丢一个事件。

## 3. 执行协议（每个施工 agent 必读）

### 3.1 环境与验证


### 3.2 铁规

1. **一次只做一个分包文档里的一个小节。** 完工标准 = 该小节的「验收」全部通过。
2. **回归测试与修复同提交。** 每个 bug 修复必须带一个"修复前必红、修复后必绿"的测试。
3. **测试全程保持绿。** 不允许"先改破再修回来"的中间态落到仓库。
4. **遵守 AGENT.md**：五条铁律、已确立的实现约定、占位桩约定，全部有效。
   mypy 是 strict，所有函数完整注解；注释与文档用中文。
5. **不引新的运行时依赖**——唯一例外是 R4 批准的 `uharfbuzz / freetype-py / fonttools`
   （决策见 docs/18 §1）。任何其他新依赖视为越界。
6. **不碰 `prototype/`**（已冻结）。不碰其他分包的范围。
7. **行号是 2026-09-12 审查时的快照**，代码漂移后以符号名/函数名为准，行号只用于定位。
8. **接口变更必须按分包文档里写明的形状落地**，不要在施工中临时发明新形状——
   发现设计有问题就停下来上报，不要绕。
9. 完工后更新：`AGENT.md` 状态表与「已知待办」、`ROADMAP.md` 对应进度行、
   本文件第 2 节表格打勾。新增/取代选型决定时，在 `AGENT.md` 的 ADR 表追加条目。

## 4. 已拍板的决策（施工时不要再争论）

1. **文本栈方向：自有 HarfBuzz + FreeType 跨平台栈，取代"三平台各用各的原生引擎"。**
   理由：docs/04 §7 的验收标准"同一文本三平台逐行一致"用平台原生引擎在数学上
   不可能达成；Flutter/Chrome/Android 的答案都是自带同一套文本栈。
   Spike 已验证可行性（见 docs/18 §1 的证据清单）。
2. **黄金图比对单位是解码后的 RGBA 像素，不是 PNG 字节。**
3. **`style/resolve.py` 的五层顺序维持现状（交互态最后）**，docs/13 §8 已按实现更正——
   理由已写在 resolve.py:12-19，把文档口径改过来。
4. **GLFW 后端删除空壳**，不维持双窗口后端（docs/19 §10）。
5. **帧缓冲所有权在后端**，`screenshot()` 是读回操作；脏矩形是 `execute` 的参数，
   不进显示列表（显示列表保持"纯图纸"）。
6. **性能断言以真实数字 + 充足余量重定**，不守着建立在假测量上的 5ms（见 docs/16 §3）。
