# 05 · 布局系统

> 一句话：**父级说"你最多能占多大"，子级说"我要占多大"——一来一回，布局就结束了。**

## 1. 模型：约束向下，尺寸向上

每个 RenderObject 实现一个方法：

```
perform_layout(constraints: BoxConstraints) -> Size
```

- 父级把 `BoxConstraints`（最小/最大宽高）传下去；
- 子级在约束内选定自己的尺寸，回报；
- 父级拿到所有子级尺寸后，决定它们的位置。
- **子级不许读父级的几何，父级不许改子级的尺寸**——只有约束这一条通道。

这就是 Flutter 验证过的模型。它比"坐标自由摆放"啰嗦一点，但换来的是：**布局永远收敛、永远可预测、永远可测试。**

## 2. 协议与脏标记

- 布局数据变化 → `mark_needs_layout()` → 帧调度收集脏节点 → 只重排脏子树。
- 约束没变的子树，直接复用上次的尺寸与位置（缓存命中）。
- 几何与位置全部存放在 RenderObject 上，布局后生成，绘制时只读。

## 3. 盒子模型

`margin → border → padding → content`，外加 **baseline 对齐**（文字基线对齐是表单看起来整齐的关键）。
对应类型已经落地：`Offset / Size / Rect / EdgeInsets / BoxConstraints`（不可变、纯数据，见 `src/inkstone/layout/types.py`）。

## 4. Flex（Row / Column）

- 主轴：`justify`（start / center / end / space-between / space-around）
- 交叉轴：`align`（start / center / end / stretch / baseline）
- 尺寸三态：固定值 / `fill`（按权重分剩余）/ 按内容
- `gap`、`wrap`（超出换行）
- 收缩规则：主轴空间不足时按 `shrink` 权重收缩，文本类默认不收缩（宁可溢出报错，不悄悄压扁）

## 5. Grid

- 轨道三态：固定 / `fr`（剩余权重）/ `auto`（按内容）
- 跨行跨列 `span`、隐式轨道（内容超出声明行列时自动生成）
- 用于表单、属性面板、仪表盘——不许拿 Grid 当全局布局滥用（那是 Flex 和 Stack 的活）

## 6. Stack、Scroll 与"无限约束"规则

- **Stack**：层叠 + `Align`（九宫格定位）+ `Positioned`（相对边距），是角标、悬浮按钮、骨架屏的地基。
- **Scroll**：滚动容器给子级的是**无限高度约束**——这必须显式，否则子级的 `fill` 会爆炸。
- **无限约束诊断**：当 `fill` 遇到无限约束，**报错并给出调用栈与节点路径**，而不是渲染一个 0 或无穷大。
  这条诊断规则能替用户省掉 80% 的"布局为什么塌了"的调试时间。

## 7. 错误诊断（企业级与玩具的分水岭）

玩具库布局错了是"界面花了"；企业库布局错了是**一条能读懂的错误**：

```
LayoutError: Row 的 fill 子节点遇到无限宽度约束
  路径: App > Column[2] > Card > Row[0] (TextInput, w="fill")
  建议: 给 Row 一个有限宽度，或把 fill 换成固定宽度
```

配套 devtools：布局检查器（每个节点的约束、尺寸、来源）见 `devtools/inspector.py`。

## 8. 验收标准

- [ ] 布局引擎 100% 无窗口可测（不开窗口跑出全部几何）
- [ ] 单测覆盖 ≥ 85%，含全部"无限约束"报错路径
- [ ] 溢出检测：内容超出容器时给出溢出标记（检查器可见），不静默裁切
- [ ] 1000 节点全量布局 < 5ms；增量（脏标记）布局 < 1ms
- [ ] 同一棵树重复布局两次，几何完全一致（确定性）
