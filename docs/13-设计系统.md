# 13 · 设计系统

> 一句话：**"精致"不是审美，是一份可验收的规格书。**
> 这份文档定义的就是那份规格——改这里的任何一个数字，全盘 UI 跟着变；反过来，任何不在规格里的样式，都不许进组件。

## 0. 为什么"精致"70% 是设计而不是工程

shadcn 看起来高级，靠的不是技术，是**克制**：颜色只有语义那一小撮、间距只有那一格、圆角只有那一档、阴影只有那五级。
设计的敌人从来不是"不够好看"，是"60 个组件各自为政"。所以这份规格的第一条是：

> **任何组件不许发明新值。** 只能用本文件定义的令牌；要加新值，先加进令牌，再使用。

## 1. 令牌三层结构

```
基础令牌（raw）        色板 12 级、字号阶梯、间距 8pt 网格、圆角、阴影参数、动效参数
   │                    —— 永远不许在组件里直接使用
   ▼
语义令牌（semantic）    surface / surface-alt / text / text-dim / primary / border / focus-ring …
   │                    —— 明暗主题的映射发生在这一层
   ▼
组件令牌（component）   button-primary-bg、input-border-focus、card-padding …
                        —— 组件只能用这一层，或语义层
```

组件里出现任何字面量颜色/字号/间距 = 审查打回。

## 2. 色彩

### 2.1 基础色板（12 级 ramp）

每个色相 12 级（50 → 950）。明度均匀过渡，用于语义层取色。内置色族：

- **中性灰**（surface 家族，低饱和、微微偏蓝）
- **品牌色**（默认 Indigo；可换）
- **状态色**：成功 / 警告 / 危险 / 信息
- **数据可视化色**：8 色定性色板 + 3 组连续色板

### 2.2 语义令牌（必须项）

| 令牌 | 亮色 | 暗色 |
|---|---|---|
| `bg` | 页面底 | 页面底 |
| `surface` | 卡片底 | 卡片底 |
| `surface-alt` | 次级底 / 输入框 | 次级底 |
| `border` / `border-strong` | 弱描边 / 强描边 | 同 |
| `text` / `text-dim` / `text-faint` | 三级文字 | 同 |
| `primary` / `primary-hover` / `primary-press` / `primary-soft` / `on-primary` | 品牌五态 | 同 |
| `focus-ring` | 焦点环 | 同 |
| 状态语义：`success` / `warning` / `danger` / `info` 各配 `bg`（浅底）+ `text`（深字） | | |

### 2.3 暗色模式不是反色

暗色 = **重新映射**，不是亮度取反。规则：
- 底越深、面越亮（surface 比 bg 亮 3–4%），用文字色阶保持层级；
- 状态色的 `bg` 用暗底低饱和版本，`text` 用高亮版本；
- 所有明暗两版必须通过 **WCAG 2.2 AA** 对比度（正文 ≥ 4.5:1，大字 ≥ 3:1）。

### 2.4 金融语义（默认，可被主题覆盖）

数据可视化默认遵守中文惯例：**涨 = 红，跌 = 绿**。
这是全局默认，不是硬编码——属于语义令牌 `market-up` / `market-down`，可被西方习惯主题一键覆盖。

## 3. 字体排印

### 3.1 字号阶梯（rem=16，中文环境取整）

| 档位 | 字号 | 行高 | 用途 |
|---|---|---|---|
| xs | 11 | 1.5 | 角标、辅助说明 |
| sm | 12 | 1.55 | 表格、次文本 |
| md | 14 | 1.6 | 正文（默认） |
| lg | 16 | 1.55 | 段落标题、输入框 |
| xl | 20 | 1.4 | 卡片标题 |
| 2xl | 24 | 1.3 | 页面标题 |
| 3xl | 30 | 1.25 | 大字报 |

**中文优化规则**：中文正文默认行高 1.5–1.65（低于 1.4 会挤）；数字与中文混排时数字用等宽特性（tnum）；正文不加字间距，标题可轻微负字距。

### 3.2 字重

只有两档：`regular(400)` 与 `medium(500)`。**禁止第三档**——重用色彩与字号区分，不靠字重堆。
bold 仅用于代码与强调标记内部。

### 3.3 字体栈

`Inter / Microsoft YaHei UI / PingFang SC / Noto Sans CJK SC / system-ui`，按平台回退；
等宽：`JetBrains Mono / Cascadia Code / Consolas`。

## 4. 间距、圆角、高度

- **间距 = 8pt 网格**：`4, 8, 12, 16, 24, 32, 48, 64`。组件内边距、gap 只能从这里取。
- **圆角**：`sm=6, md=10, lg=14, xl=20, pill=∞`。同族组件同档圆角；小控件不超过 md。
- **控件高度阶梯**：`xs=24, sm=28, md=36, lg=44, xl=52`。所有可交互控件必须从这一列取值，保证表单对齐。

## 5. 阴影与焦点环

五级 elevation（全部参数化，含颜色与透明度，不画"黑影"画"环境色影"）：

| 级 | 用途 |
|---|---|
| e0 | 无 |
| e1 | 卡片静止 |
| e2 | 悬停抬升 / 下拉 |
| e3 | 弹层（Popover/Menu） |
| e4 | 模态对话框 |

**焦点环**：`2px focus-ring 色 + 2px 偏移`，永不裁切，键盘导航必备，鼠标点击不显示（focus-visible 语义）。

## 6. 动效令牌

### 6.1 时长

`75ms（微交互）/ 150ms（悬停）/ 200ms（进入）/ 300ms（离开/大位移）/ 500ms（页面级）`。
超过 500ms 的动效 = 审查打回。

### 6.2 缓动

| 名称 | 曲线 | 用途 |
|---|---|---|
| ease-out-expo | cubic-bezier(0.16,1,0.3,1) | 进入 |
| ease-out-quart | cubic-bezier(0.25,1,0.5,1) | 悬停/微交互 |
| ease-in-quart | cubic-bezier(0.5,0,0.75,0) | 离开 |
| ease-in-out-quart | cubic-bezier(0.76,0,0.24,1) | 位移/尺寸 |
| spring-default | 质量1 / 刚度170 / 阻尼26 | 可中断的物理感 |
| spring-gentle | 质量1 / 刚度120 / 阻尼20 | 弹层、大元素 |

### 6.3 减少动效

读取系统 `prefers-reduced-motion`。开启时：所有动画降为瞬时或 75ms 淡入淡出，弹簧禁用。
**这是无障碍要求，不是可选项。**

## 7. 密度

三档：`comfortable（默认）/ compact（数据密集）/ spacious（消费级）`。
密度只影响间距与控件高度，不影响字号与圆角。

## 8. 组件配方（anatomy）——形态规范

复杂组件必须是**组合式**的，不能是巨型单类。规范：

```
Dialog
├─ Dialog.Trigger      触发器
├─ Dialog.Portal       传送门（primitives/portal）
├─ Dialog.Overlay      遮罩（dismissible + scroll_lock + presence）
├─ Dialog.Content      内容（focus_trap + popper 无 / presence + 动效）
│   ├─ Dialog.Header / Title / Description
│   ├─ Dialog.Body
│   └─ Dialog.Footer / Close
```

每个 part：声明 `as`（渲染为什么元素）、`style`（令牌槽位）、`data-*` 状态属性（`data-state=open`、`data-disabled`）。
状态一律走 data 属性，样式按 data 属性解析——**可预测、可被 AI 稳定生成、可被测试快照**。

### 状态轴（所有交互组件统一）

`default / hover / active / focus-visible / disabled / loading / selected / error`
样式解析顺序（确定性，无优先级战争）：默认 → 主题 → 变体(variant/size/tone) → 实例覆盖 → 交互态。

**交互态放最后**：如果实例覆盖能压过状态，用户写一句 `bg=red`，悬停反馈就被悄悄关掉了——
这是最难排查的那类 bug（"我明明设了 hover 色，怎么没反应"）。让状态永远生效、
实例覆盖只管"静态外观"，职责更清楚。（这条曾与 `style/resolve.py` 有分歧，现已按实现定稿。）

### Button 示例（变体配方）

```
variant: primary | secondary | outline | ghost | danger | link
size:    xs | sm | md | lg | xl
tone:    brand | neutral | success | warning | danger（与 variant 组合，不叠乘）
state:   上表八态
parts:   root（含 loading spinner 槽）、icon-left、label、icon-right
```

## 9. 验收标准（"精致"如何被证明）

- [ ] 组件库内全文搜索：`#[0-9a-fA-F]{6}` 与硬编码字号/间距数量为 **0**（只允许令牌名）
- [ ] 明暗两版全部语义令牌对比度 ≥ WCAG 2.2 AA，自动化检查进 CI
- [ ] 所有交互控件高度 ∈ 高度阶梯；所有间距 ∈ 8pt 网格
- [ ] 黄金图覆盖：每个组件 × 每变体 × 每状态 × 明暗两版
- [ ] 减少动效开启时，全库无 > 75ms 的动画（自动化检测）
- [ ] 键盘可达：不用鼠标可完成组件示例库的全部操作
- [ ] 图标与文字基线对齐误差 ≤ 1px
