# 02 · 平台后端与跨平台矩阵

> 一句话：**把 Windows / macOS / Linux 的脾气，全部关在这一个房间里。**
> 楼上任何一层都不许知道自己在哪个操作系统上——这是跨平台成立的前提。

## 1. PAL（平台抽象层）的职责边界

**进来**：窗口、事件、输入法、剪贴板、光标、DPI、文件对话框、系统通知、托盘、字体目录。
**不出去**：任何平台判断。上层出现 `if sys.platform == ...`（除本层）= 审查打回。

## 2. 后端协议（Backend Protocol）

后端必须实现的最小接口集：

| 能力 | 接口要点 |
|---|---|
| 窗口 | 创建/销毁、尺寸、标题、最小尺寸、全屏、多窗口、失焦/聚焦回调 |
| 帧循环 | 请求重绘（vsync 对齐）、当前时间戳 |
| 事件泵 | 归一化事件流：指针、键盘、滚轮、文本输入、IME 组合 |
| IME | 开始/结束文本输入、**设置候选框位置**、组合态文本与光标区间 |
| DPI | 当前缩放因子、跨屏移动时的变化通知 |
| 光标 | 系统光标（箭头/手型/文本/十字/缩放）与自定义位图光标 |
| 剪贴板 | 文本、图片读写 |
| 对话框 | 原生打开/保存文件、选目录、消息框 |
| 其他 | 拖放文件入窗、系统通知、托盘（插件化） |

## 3. 后端选型（ADR-0001）

| 候选 | 优势 | 致命伤 | 结论 |
|---|---|---|---|
| **SDL2** | 三平台成熟、原生 Wayland、**完整 IME 组合事件 + 候选框定位**、游戏级输入 | 二进制分发要打包 | **首选** |
| GLFW | 更轻 | **没有 IME 组合 API**，中文输入残废 | ~~备选降级~~ **已否决并删除（R5.11）** |
| winit (Rust) | 最现代 | 引入 Rust 工具链，违背"纯 Python" | 暂不采用 |
| pyglet | 纯 Python | Wayland 走 XWayland、macOS 后端薄弱 | 已用于 Phase 0 探针，退役 |

**决定：SDL2 是唯一窗口后端，headless 用于测试（R5.11 定稿）。**
理由一句话：中文输入法是硬门槛，SDL2 是唯一把 IME 组合态和候选框定位都给了
API 的跨平台库。GLFW 过不了这个硬门槛——一个通不过硬门槛的"降级方案"
不是降级方案，其空壳已随 R5.11 删除。

## 4. 跨平台能力矩阵

| 能力 | Windows 11 | macOS 13+ | Linux X11 | Linux Wayland |
|---|---|---|---|---|
| 窗口/多窗口 | ✅ | ✅ | ✅ | ✅ |
| 高 DPI / 逐屏缩放 | ✅ | ✅ | ⚠️ 部分 | ✅ |
| IME 组合态 | ✅ IMM/TSF | ✅ NSTextInputClient | ✅ XIM/IBus | ✅ text-input-v3 |
| 候选框跟随光标 | ✅ | ✅ | ✅ | ✅ |
| 系统菜单栏 | 窗口菜单 | **全局顶部菜单** | 桌面环境差异 | 同左 |
| 托盘/通知 | ✅ | ✅ | ⚠️ 依桌面环境 | ⚠️ 依桌面环境 |
| 文件对话框 | ✅ 原生 | ✅ 原生 | ✅ XDG portal | ✅ XDG portal |
| 剪贴板/拖放 | ✅ | ✅ | ✅ | ✅ |
| 字体发现 | DirectWrite | CoreText | fontconfig | fontconfig |

**降级原则**：标注 ⚠️ 的能力，上层必须有无感降级（如托盘不可用时，功能迁移到窗口菜单）。降级不许丢功能，只许换位置。

## 5. IME 详解（中文体验的深水区）

三平台机制完全不同：

- **Windows**：IMM32 + TSF 双轨。`SDL_SetTextInputRect` 告诉系统光标位置，候选框出现在正确位置；组合文本经 `SDL_TEXTEDITING` 上报（含下划线区间与光标）。
- **macOS**：`NSTextInputClient` 协议。候选框定位用同一 API；macOS 特有"组合文本属性串"，需要映射为内部统一结构。
- **Linux**：X11 走 XIM/IBus，Wayland 走 `text-input-v3`。IBus/Fcitx 行为有差异，需真机测试覆盖搜狗、IBus 默认、Fcitx5。

**统一内部模型**：`composing(bool)` / `composition_text` / `composition_cursor` / `committed_text`。
输入框组件只面对这个模型，不面对平台。
**测试要求**：三个平台各覆盖至少一款主流中文输入法，含长组合、翻页选词、退格取消组合。

## 6. DPI 与缩放

**换算口径（R7.3 落地，实现见 `core/binding.py` / `devtools/screenshot.py`）：**

- 布局永远用**逻辑像素**：约束、尺寸、offset、命中测试、事件坐标全是逻辑像素。
  组件代码不知道 DPI 的存在，也不许自己乘缩放因子。
- **物理像素 = 逻辑像素 × `dpi_scale`**，换算只发生在**录制/光栅那一层**：
  后端把档位交给 `BuildOwner.begin_frame(dpi_scale=…)`，录制时由
  `flush_paint` 在根上压一个等比仿射变换，于是显示列表里的指令坐标是设备像素，
  帧缓冲按 `逻辑尺寸 × scale` 分配。线宽、圆角、字形 em 一起缩放（R3.4），
  文字在**物理分辨率上重新光栅化**（掩码缓存键含生效字号，不含 1.0 档的旧掩码）。
- 后端事件里的 `DPI_CHANGED` 经 `BuildOwner.handle_window_event` 更新档位；
  跨屏拖动（150% → 100%）时下一帧就按新档位重新录制，**不许拉伸旧帧**（那会模糊）。
- 验收：100% / 125% / 150% / 200% 四档截图基线，逐像素容差为 0（文字）与 ≤1px（几何）。
  当前已建 100% 与 150% 两档基线（`login_form_light` / `login_form_light_150`）。

## 7. 系统对话框与原生组件策略

**决定：文件对话框、系统消息框用原生；菜单栏用原生（macOS 全局菜单是系统行为）；其余全部自绘。**
理由：这三类是用户肌肉记忆所在，自绘反而"不原生"；而按钮、列表、表格自绘才能保证设计系统一致。

## 8. headless 后端（测试与 CI 的生命线）

- 不开窗口，离屏渲染到内存位图，供黄金图测试与自动化测试。
- 时钟、随机数、DPI 全部可注入——这是"确定性"原则在测试层的落地。
- CI 三平台全部跑 headless；真窗口测试只在带显示的 runner 上标记运行。
