# 07 · 样式与主题（机制）

> 一句话：**`docs/13` 定义"值"（用什么色、多大圆角），本文定义"机制"（这些值怎么流进组件）。**

## 1. 令牌三层（机制视角）

```
基础令牌 ──解析──▶ 语义令牌 ──解析──▶ 组件令牌 ──解析──▶ 具体样式值
（raw）              （semantic）        （component）         （组件运行时只见这层）
```

主题切换 = 换掉中间那一层的映射表。组件永远不知道当前是明是暗。

## 2. 确定性级联（不实现全局 CSS 选择器，ADR-0004）

样式解析顺序固定，无优先级战争：

```
默认值 → 主题 → 变体（variant/size/tone）→ 状态（hover/focus/disabled…）→ 实例覆盖
```

**为什么不支持全局选择器**：`.card .button:hover` 这类规则，优先级计算对人是玄学、对 AI 是灾难、对测试是地狱。
我们的替代：**样式即数据**——每个组件声明自己的样式槽位，样式以 dict 传入，可序列化、可快照、可 diff。
AI 生成 dict 几乎不出错，生成选择器经常出错。这是"为 AI 而生"在样式层的落地。

## 3. 变体配方（Variants as Data）

每个组件声明变体轴与配方：

```python
BUTTON_RECIPE = {
    "variant": {"primary": {...}, "outline": {...}, "ghost": {...}, "danger": {...}},
    "size":    {"sm": {...}, "md": {...}, "lg": {...}},
    "tone":    {"brand": {...}, "neutral": {...}, "danger": {...}},
    "default": {"variant": "primary", "size": "md", "tone": "brand"},
}
```

- 配方 = 纯 dict，定义一次，解析成组件令牌；
- 配方可注入：用户/AI 可以提供自己的配方覆盖默认（自定义的入口，不是改源码）；
- 组合数爆炸由解析器处理，配方只写有意义的组合。

## 4. 状态样式与 data 属性

交互状态一律映射为节点的 `data-*` 属性：`data-hover`、`data-focus-visible`、`data-disabled`、`data-state="open"`。
样式按 data 属性解析——**状态一眼可见、可快照、可被检查器读取**，而不是藏在事件回调的临时变量里。

## 5. 主题

- 内置 `light` / `dark`；支持跟随系统（后端上报系统主题变化）。
- **局部主题**：子树可以覆写主题片段（如：亮色应用里嵌一个深色代码块），作用域仅限该子树。
- **主题即数据**：主题 = 语义令牌映射表（dict），用户主题 = 提供新映射表，无需继承类。
- 字号缩放（无障碍）与密度（comfortable/compact/spacious）是主题的两个正交维度，互不影响。

## 6. 与动效的关系

样式值标记为"可动画"后，值变化时由 `motion/` 按令牌中的时长/缓动自动插值——
主题切换不是瞬变，是 200ms 的渐变。减少动效开启时退回瞬变。

## 7. 验收标准

- [ ] 主题切换一行代码完成，全库 200ms 内完成过渡，无闪烁
- [ ] 样式解析结果可序列化；同一输入两次解析结果一致（确定性）
- [ ] 局部主题只影响子树，退出子树后完全还原
- [ ] 配方注入：不改库源码，新增一个按钮 variant 并出现在检查器中
- [ ] 全文搜索：组件代码中无硬编码颜色/字号/间距（CI 拦截）
