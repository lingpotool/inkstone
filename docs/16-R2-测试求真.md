## R2.1 黄金图比对单位：PNG 字节 → 解码后像素

**根因**：`encode_png` 用 `zlib.compress(raw, level=6)`（`gfx/raster/software.py` 内）。
deflate 输出不跨 zlib 版本保证一致，而各平台 CPython 打包的 zlib 并不固定——
"三平台逐字节一致"（AGENT.md 现有口径）是侥幸，不是保证。

**修法**：

1. 在 `tests/` 下新增 PNG 解码助手（如 `tests/png_compare.py`）：stdlib `zlib` + 手写
   PNG un-filter（5 种滤波器都要：None/Sub/Up/Average/Paeth），解码为 RGBA bytes。
   只支持我们自己编码器产出的形态（8-bit RGBA、非交错）即可，拒绝其他形态时响亮报错。
   **不引 Pillow 等依赖。**
2. 黄金图断言改为：**解码后的 RGBA 逐字节相等**。PNG 文件字节只作存储格式。
   涉及 `tests/unit/test_golden_form.py`、`tests/unit/test_text_render.py` 的比对处。
3. 更新 AGENT.md 中"逐字节相同"的口径描述（改为"像素级一致"）。

**测试**：解码器自身的往返测试（encode→decode 全等）；构造两张差 1 像素的图断言比对能发现。

## R2.2 基线缺失 = 失败

**根因**：`test_golden_form.py:83-86`、`test_text_render.py:56-59`：
`if os.environ.get(UPDATE_ENV) == "1" or not baseline.exists(): write; return`——
基线缺失时直接写新基线并绿灯。

**修法**：非更新模式下基线不存在必须 fail，报错信息带修复指引
（"若这是新场景：`INKSTONE_UPDATE_GOLDEN=1 pytest <文件>` 生成基线并肉眼确认"）。

**测试**：删掉一张临时基线跑对应测试，断言失败且信息含指引（用 tmp_path 隔离，不动真基线）。

## R2.3 性能基准测真全量

**根因**：`tests/unit/test_layout_perf.py:66-75` 每轮只调 `root.mark_needs_layout()`，
而该方法只向上冒泡——第二轮起 250 个 Row 与 750 个叶子全部缓存命中，
"1001 节点 0.89ms"实测的是一次根节点布局 + 250 次缓存查询。
审查实测：**真全量 14.6ms**（1001 节点全部标脏），超 docs/05 §8 的 5ms 预算近 3 倍。

**修法**：

1. 新增"递归标脏整棵树"的测试辅助（或给 RenderBox 加一个测试用的 `mark_tree_dirty()`）；
2. 基准拆成两个用例并改名以示诚实：
   - `test_layout_perf_incremental`（现状那个）——增量布局预算，保留；
   - `test_layout_perf_full`——真全量。**预算定为 30ms**（本机实测 14.6ms，
     CI runner 按 2 倍余量；墙上时钟断言不许收紧，这是 AGENT.md 的既有原则）。
3. 口径修正：ROADMAP「1001 节点全量布局 0.89ms」与 AGENT.md「实测 0.9ms」改为
   增量数字，并注明真全量数字与预算。
4. 性能优化本身（constraints 对象复用、`children` tuple 缓存）**不在本包**，
   记入 docs/20 后补清单。

**验收**：`pytest -m slow` 绿；两个用例名出现在报告里；文档口径一致。

## R2.4 "组件零硬编码"扩到数值令牌 + 清理漏网

**现状**：`test_architecture.py:230-243` 只扫 `#[0-9a-fA-F]{6}`。漏网（审查实锤）：

- `widgets/basic.py:115` `radius = self.radius or 10.0`（paint 期硬编码回退，活代码）；
- `widgets/basic.py:123` `stroke(rect, 1.0, ...)`（描边宽写死）；
- `widgets/form.py:70-84` 一组 render 对象默认字面值（36.0/1.0/10.0/12.0）；
- `widgets/basic.py:84` `elevation: str = "e1"` 字段从未被读取（阴影光栅端未实现）。

**修法**：

1. 前两类改为从 `style/tokens.py` 取值（没有对应令牌就先加令牌，铁律 2）；
2. form.py 的死默认值：要么来自令牌，要么删掉让必填字段必填；
3. `elevation` 字段：**删除**（pre-1.0，不留谎称有阴影的 API；阴影落地时再加回）；
4. 架构测试扩展：在 `widgets/` 范围扫描圆角/描边宽度/控件高度三类数值字面量
   （窄扫描，宁可漏不可吵——误报多的扫描会被忽略，比没有更糟）。

**验收**：四处漏网清零；新增扫描有"故意放一个硬编码会红"的自验证用例。
