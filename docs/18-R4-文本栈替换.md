# 18 · R4 文本栈替换：HarfBuzz + FreeType

> 前置：R2（测试求真）、R3（PositionedGlyph.y_offset）。
> 这是地基整改的核心包。方向已拍板（docs/14 §4-1）：**自有跨平台文本栈，
> 取代"三平台各用各的原生引擎"**。

## 1. 依据与已验证事实

**为什么必须换**（审查结论，不是口味问题）：

- docs/04 §7 的验收标准"同一文本在三个平台的行数与行高一致"，用
  DirectWrite/CoreText/fontconfig 三套引擎**在数学上不可能达成**——
  同一字体文件过三套整形器，行宽就是不一样；
- 现有 `GdiFontEngine` 是原型级实现：逐簇 `TextOut`（kerning/连字从构造上不可能）、
  字号取整（125% DPI 必丢 0.5px）、Python 逐像素读回 DIB（每字形一次双重循环）、
  无彩色 emoji、无可变字体；
- Flutter / Chrome / Android 的答案一致：自带 HarfBuzz（整形）+ FreeType（光栅化）。

**Spike 已验证**（参考实现：仓库根目录 `_spike_hbft.py`，约 250 行，本包落地后删除）：

- 通过现有 `MetricsProvider` + `GlyphProvider` 协议**零改动**插入架构，
  渲染 hello 界面与 GDI 版逐行一致（`_hello_hbft.png` 可对照）；
- kerning 真实生效：Segoe UI 20px 下 "To"=20.25px，比逐字宽度之和收紧 1.95px；
- 小数字号生效：17.5px 下"中文测试"= 70.00px；
- 字体发现正常：扫描出 225 个系统族，TTC 子面处理正确；
- 依赖全是纯 pip 轮子（cp313/win 实测可装）：`uharfbuzz 0.56.1`、`freetype-py 2.5.1`
  （轮子自带 DLL）、`fonttools 4.65.0`。

## 3. 施工步骤

### R4.1 `backend/fontfiles.py` —— 字体库（L0a）

职责：字体文件的**发现、加载、解析、匹配**。

- 系统字体索引：扫描平台字体目录（Windows `C:\Windows\Fonts`、macOS
  `/System/Library/Fonts` + `~/Library/Fonts`、Linux fontconfig 路径），
  用 fontTools 读 name 表（优先 nameID 16 typographic family，退回 nameID 1），
  建 `族名 → (路径, face_index)`；TTC/OTC 枚举子面；结果缓存（启动一次）。
  参考 `_spike_hbft.py` 的 `build_family_index`。
- **用户字体注册**：`register_font_file(path)` → 解析族名/字重/斜体并入索引——
  这是 CSS `@font-face` 的等价物，用户自定义字体的地基。
- **字重/斜体匹配**：同一族内按 CSS font matching 语义选最近字重
  （400/500/600/700 枚举值映射见现有 `FontWeight`），不再忽略字重轴
  （spike 的已知欠账，本包必须还）。
- 分层纪律：本模块在 L0，可用平台路径知识；`text/` 不许碰（架构测试守着）。

### R4.2 `backend/hbft_fonts.py` —— 整形与度量（L0b/c）

把 spike 扶正为产品实现，同时实现 `MetricsProvider` 与 `GlyphProvider`
（同一对象，度量与字形同源——ADR-0009 的精神延续）。

- **整形**：uharfbuzz，`font.scale = (size*64, size*64)` + `hb.ot_font_set_funcs()`；
  位置值是 26.6 定点，除以 64。
- **度量**：advance 只从整形结果出；ascent/descent 从 FreeType `face.size`
  （`set_char_size(int(size*64))`——**小数字号，不许取整**）。
- **簇映射**：HarfBuzz 的 cluster（源串下标）→ `grapheme_clusters()` 的字素簇。
  注意连字情形：一个 hb 簇可能覆盖多个字素簇（"ffi" 一形三字），
  advance 按簇内字素簇个数均分并在注释里说明取舍；命中测试按下标映射仍正确。
- **缺字探测**：为回退链提供"这个字体有没有这个字符"的能力
  （cmap 查询，fontTools 或 FreeType `get_char_index`）。
  **这是现有 `MetricsProvider` 协议没有的**——协议增加 `has_glyph(family, char) -> bool`，
  `text/fallback.py` 的逐脚本选族从"族存在"升级为"族覆盖该脚本的字符"。
- **光栅化**：`face.load_glyph(gid, FT_LOAD_RENDER | FT_LOAD_TARGET_NORMAL)`，
  灰度掩码；`mask_for` 的缓存键含（文本、字号、族）。
- 错误处理：字体文件损坏、族不存在、空串——响亮失败或文档化的空掩码，不许静默。

### R4.3 run 级光栅化（连字的最后一块）

**现状**：`GlyphProvider.mask_for(text=单簇)` 逐簇取字形——连字拿不到
（spike 的限制，继承自架构而非实现）。

**修法**：`TextRunOp` 的 `PositionedGlyph` 增加可选的 `glyph_id` 与 `family`/`size`
（若已在 R3 加过 `y_offset`，此处补全剩余字段）；`GlyphProvider` 增加可选方法
`masks_for_run(...)`，文本层在整形后直接把 hb 的 glyph id 序列传下来——
光栅层按 glyph id 取掩码，绕开"按文本重新整形"。
`mask_for` 保留为降级路径。**决策点**：若改动面过大，允许分两阶段——
先落 R4.2（kerning 有、连字无），连字作为 R4 收尾项，但不许不写进本包。

### R4.4 内嵌 OFL 兜底字体

- 选 **思源黑体/Noto Sans CJK SC**（OFL 许可，可再分发——docs/04 §4 已确认）；
- 用 `fonttools subset` 做子集化（GB 常用汉字 + ASCII + 标点 + 常用符号），
  控制体积（目标 < 5MB；全量 CJK 字体 ~10-16MB 不可接受）；
- 放 `src/inkstone/backend/fonts_data/`，附 LICENSE 文件；
- 回退链终点从"系统默认"改为"内嵌字体"——**中文永不出豆腐块**获得结构保证，
  不再赌用户系统装了什么；
- `has_family`/`resolve_font` 对兜底族名永远命中。

### R4.5 真字体黄金图

- 黄金图从确定性 5×7 字形切到**内嵌字体 + FreeType**——同字体文件 + 同 FreeType
  版本在三平台逐比特一致（Flutter 的黄金图就是这么做的）；
- 确定性 `BuiltinGlyphProvider` **保留**：它仍是零依赖的最小验证后端，
  用于"没装字体依赖也能跑测试"的场景；
- 7 张既有基线全部重生成（像素级比对，R2 已就位），肉眼确认；
- 新增黄金图场景：中英混排、kerning 词对（"To"/"AV"）、小数字号（17.5px）、
  CJK 禁则折行的真字形版。

### R4.6 删除 GDI

- 删除 `backend/gdi_fonts.py` 与其测试；`HeadlessBackend(system_fonts=True)`
  的语义改为注入 HB+FT 引擎；
- CI 的 coverage 任务说明同步更新（AGENT.md 里"GDI 只能在 Windows 上量"的
  段落改写——HB+FT 是三平台的，这个坑不存在了）；
- ADR 表新增 **ADR-0011**（自有文本栈取代平台原生引擎），在 ADR-0009 条目上
  标注"已被 ADR-0011 取代"；docs/04 §2 的"平台 API"选项改写；
- 删除根目录诊断产物：`_spike_hbft.py`、`_diag_baseline.py`、`_hello_*.png`。

## 4. 验收

- `make check` 全绿；三平台 CI 的黄金图在**真字体栈**上像素级一致；
- 测试钉住：kerning（"To" < "T"+"o"）、小数字号、字重选择、内嵌字体兜底
  （把系统链全断掉仍出真汉字）、连字（若 R4.3 完成）；
- `has_glyph` 驱动的回退：主字体缺某字符时逐簇回退有测试；
- `grep -r gdi_fonts src/` 零命中；
- hello.py 出图与 GDI 版肉眼对照（中文观感不劣化）。

## 5. 明确不做（本包范围外）

- 彩色 emoji（COLR/CBDT）——协议留位，实现属 Phase 3；
- 复杂脚本整形的质量验证（阿拉伯语等）——HarfBuzz 本身保证了正确性，测试后补；
- 可变字体的轴调节 API——匹配算法先按静态字重做；
- subpixel LCD（ClearType 式）渲染——灰度 + 次像素定位是现代标准，不做。
